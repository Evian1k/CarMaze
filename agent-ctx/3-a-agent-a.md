# Task 3-a — Identity & security: password reset, email verification, TOTP MFA, auth UI upgrades

## Status: COMPLETE (end-to-end QA'd via HTTP; 1 operational note, see "Deviations / notes")

## Files created
- `src/lib/totp.ts` — pure-node (no new deps) RFC 6238 TOTP: base32 encode/decode (RFC 4648, padding/space tolerant), `generateTotpSecret()` (20 random bytes → base32), `verifyTotp(secret, code, window=1)` (SHA1, 6 digits, 30s step, ±1 step drift, constant-time `timingSafeEqual` compare), `totpUri(secret, account)` → `otpauth://totp/CARMAZE:<email>?secret=…&issuer=CARMAZE`. Also hosts `signMfaChallenge(userId)` / `verifyMfaChallenge(token)` — short-lived (5 min) `scope:'mfa'` JWTs signed with the same AUTH_SECRET as session cookies. They live here because `src/lib/auth.ts` is scoped to the long-lived session contract only.
- `src/app/api/auth/forgot-password/route.ts` — POST {email}; rateLimit `forgot-password:${ip}` 5/h; case-insensitive email lookup (exact first, then `contains` + verify — SQLite has no `mode:'insensitive'`, mirrors register's findReferrer pattern); ACTIVE users only: delete previous unused tokens → create token `randomBytes(32).hex`, store sha256(token) as `tokenHash`, 60-min expiry, requestIp. Audit `PASSWORD_RESET_REQUESTED` (metadata `{ userId }` only — no email). ALWAYS generic `{ ok, message }`; when no SMTP and non-production, matching account additionally gets `devResetToken` / `devResetPath: '#/signin?reset=…'` / `devNotice` (honest dev channel, verify-phone pattern).
- `src/app/api/auth/reset-password/route.ts` — POST {token(min16,max128), password(min8,max100)}; rateLimit `reset-password:${ip}` 10/h; sha256 lookup → `404 INVALID_TOKEN` / `400 TOKEN_EXPIRED` / `400 TOKEN_USED`; `$transaction` sets bcrypt passwordHash + usedAt; audit `PASSWORD_RESET_COMPLETED`.
- `src/app/api/auth/verify-email/route.ts` — POST {action:'request'|'confirm'}; request: requireUser, rateLimit `verify-email:${userId}` 5/h, `sixDigitCode()` stored on `User.emailCode`, response shape mirrors verify-phone exactly (`{sent, channel:'email'|'dev', devCode?, message}`); confirm: code compare → `emailVerified=true`, clear code, audit `EMAIL_VERIFIED`, `{verified:true}`; wrong code → 400 INVALID_CODE.
- `src/app/api/auth/mfa/setup/route.ts` — requireUser, rateLimit 10/h; 409 MFA_ALREADY_ENABLED if enabled; generates secret, saves `totpSecret` (mfaEnabled stays false), audit `MFA_SETUP_STARTED`, returns `{secret, uri}`.
- `src/app/api/auth/mfa/enable/route.ts` — requireUser, rateLimit 10/15min; needs stored secret; `verifyTotp` else 400 INVALID_CODE; sets mfaEnabled, audit `MFA_ENABLED`, `{enabled:true}`.
- `src/app/api/auth/mfa/disable/route.ts` — requireUser, rateLimit 5/h; `verifyPassword` else 403 WRONG_PASSWORD (audit `MFA_DISABLE_FAILED`); clears totpSecret + mfaEnabled, audit `MFA_DISABLED`, `{enabled:false}`.
- `src/app/api/auth/mfa/verify/route.ts` — NO session required: rateLimit `mfa-verify:${ip}` 15/15min; verifies challenge JWT (401 MFA_SESSION_EXPIRED on bad/expired/scope mismatch/inactive user), `verifyTotp` (400 INVALID_CODE, audit `MFA_LOGIN_FAILED`), then `createSession` + audit `MFA_LOGIN_SUCCESS` + returns login-success user shape (plus the three new fields).
- `.env.example` — DATABASE_URL, AUTH_SECRET, SMTP_URL, SMS_API_KEY, MPESA_* (5 vars), MPESA_ENV, NEXT_PUBLIC_SITE_URL with one-line comments + honest notes (SMS/SMTP optional; dev fallbacks returned in responses; M-Pesa never simulated).
