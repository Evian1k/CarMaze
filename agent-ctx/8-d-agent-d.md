## API mismatches / notes for integrators
1. **Credit approve cannot set the limit** — task said "set limit + deposit + terms", but `PATCH /api/org/credit/[id]` schema only accepts `{action:'approve', terms, depositMinor?}`; the limit stays the customer's `requestedLimitMinor`. Review dialog shows it read-only ("set by the customer's application").
2. **No "apply for credit" POST from the customer UI in SubscriptionsPanel** — per task instruction the CTA is copy-only ("ask your garage or showroom to send an offer"). Backend `POST /api/org/credit` (customer apply) exists and is fully wired-shaped if wanted later.
3. **Vehicle list for transfers** — used `GET /api/vehicles?mine=1&orgId=` (documented in code); `mine=1` returns org vehicles with status but **no `branchId`** — source-branch resolution is left to the backend (it derives from `vehicle.branchId` or the primary branch). Dealer dashboard inventory was the fallback; not needed.
4. **Trust GET `status`** — programme has `status: 'ACTIVE'|'PAUSED'` but there is no PATCH to pause; shown read-only.
5. **Membership `redemptions`** carry only `periodKey` (no benefit-per-period flag on the tier) — "used this period" derived client-side by matching `periodKey` to current month; period keys are calendar months server-side.
6. **`summary.pendingPayments` is a money amount** (sum of pending invoice minors), not a count — rendered as money with a count hint computed locally.
7. Route registration: `#/memberships` is NOT yet in `src/app/page.tsx` VIEWS map (out of scope — do-not-modify rule). Integrator should add `memberships: dynamic(() => import('@/views/memberships'), …)`; account/dealer/garage-dashboard owners compose `SubscriptionsPanel` (account tab `subscriptions`), `MembershipsManager` (garage/dealer `?tab=memberships`), `BranchManager`/`TransfersPanel` (`?tab=branches` — TransfersPanel under DEALER only).
