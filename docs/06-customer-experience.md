# PARTS 6 + 11 — THE CUSTOMER EXPERIENCE · VEHICLE PASSPORT & MY GARAGE

Step-by-step through every customer-facing surface: what the customer sees, what they can do, and what happens behind the scenes. (Behind-the-scenes detail is summarised here; full request traces are in [04-system-workflows.md](04-system-workflows.md).)

## 6.1 Homepage (`#/`)

- **Sees**: cinematic hero (admin-configurable copy via the `home_hero` system setting, with a coded fallback), search form (keyword + body type + county), trust marquee (static), **Featured vehicles** (4) and **Recently added** (8) as live `VehicleCard`s, a modules grid linking all main surfaces, sell/trust/dealer strips, footer.
- **Behind the scenes**: `GET /api/vehicles/home` (public; 60s cache headers) returns featured/recent PUBLISHED vehicles + real counts (published listings, active dealer orgs, active garage orgs) and increments campaign **impressions** for featured vehicles. `GET /api/settings/home-hero` degrades to null on corruption (homepage never crashes).
- **First visit**: a 7.6s cinematic intro (`/video/intro.mp4`, generated by AI once via script) with Skip; skipped for reduced-motion users, deep links, and repeat sessions; video skipped on save-data/2G.

## 6.2 Registration & login (`#/signin`)

Covered in Part 4.1/4.2. Extras visible to the customer: dev-mode verification codes shown in-UI with an explicit "email/SMS not configured" note; the **Demo accounts** section listing 8 sandbox personas (no credentials in the payload); referral capture via `?ref=`; MFA step-up screen; forgot/reset password flow (60-minute single-use token, sha256-hashed at rest; dev shows the reset link).

## 6.3 Customer dashboard (`#/account`) — 12 tabs

| Tab | What the customer can do | Behind the scenes |
|---|---|---|
| `profile` | Edit phone (verification resets on change), verify email/phone, enrol/disable TOTP 2FA, read privacy card | `PATCH /api/auth/profile`, `POST /api/auth/verify-{email,phone}`, `/api/auth/mfa/*`; codes are 6-digit (dev-shown), no expiry on codes (documented gap) |
| `saved` | Grid of saved vehicles with unsave | `GET/POST/DELETE /api/saved-vehicles`; privacy guard: saved vehicles disappear from the list if unpublished (unless own) |
| `enquiries` | All sent enquiries as chat threads; close | `GET /api/enquiries?mine=1`; replies/closure per Part 4.3 |
| `messages` | Two-pane inbox with businesses (attachments, day separators, closed-thread lock) | `MessagesTab scope="mine"` → `/api/conversations?scope=mine`; open marks read server-side |
| `requests` | Service/quote requests with quotes received; **Accept/Decline quotes**; booking status | `GET /api/service-requests?mine=1`, `PATCH /api/quotes/[id]`; accept creates the Booking (Part 4.7) |
| `orders` | Parts orders: cancel (SUBMITTED), confirm receipt (DELIVERED), dispute, **pay invoice via M-Pesa**; shows only the OTP hint (full code lives in notifications) | `GET /api/orders`, `POST /api/orders/[id] {action}`, `POST /api/billing/mpesa/stkpush` |
| `searches` | Save/rename/delete up to 20 searches with the exact query string | `/api/saved-searches` (409 on cap/duplicate). `alertsOn` exists but **no alert engine runs** (honest gap) |
| `rewards` | Loyalty points balance (CountUp), referral code + invite link, ledger, rules | `GET /api/loyalty/summary`; points only from REFERRAL_SIGNUP (+500), REVIEW_EARNED (+100, first review per org), SERVICE_COMPLETED (+250), ADJUSTMENT |
| `protection` | Full Vehicle Protection cockpit (see §6.14/Part 11) | `/api/custody?mine=1`, `/api/incidents?mine=1` |
| `subscriptions` | Business memberships (cancel; per-benefit redemption state), trust labels, credit facilities (accept terms, repay), pending invoices with M-Pesa pay | `GET /api/account/subscriptions` (lazy-expires stale memberships), `PATCH /api/memberships/manage`, `/api/org/credit/*` |
| `testdrives` | Booked drives with odometer/fuel trail; cancel while REQUESTED/CONFIRMED | `GET /api/test-drives?mine=1`, 15s refresh |
| `notifications` | Inbox list, mark-all-read, deep links | `GET /api/notifications?take=30`, `PATCH {all:true}` |

Error handling is explicit: a load failure renders a banner with Retry — the app never renders an error as an empty state.

## 6.4 Vehicle marketplace (`#/cars`)

- **Sees**: AI Car Finder panel; filter sidebar/sheet (make, model, body type, county, fuel, transmission, condition, seller type, verified-only, price/year/mileage ranges) with a live count badge; sort (newest/price ↑↓/mileage/views); compare bar (up to 3 vehicles → 9-row spec comparison dialog); save-to-search; pagination; 8-card skeletons while loading; explicit "no vehicles match" + clear-filters state.
- **Behind the scenes**: URL is the state (`#/cars?q=…&minPrice=…`, prices in minor units, 400ms debounced replace) so searches are shareable; `GET /api/vehicles` returns only `PUBLISHED` vehicles with server-side filters/sort/pagination (12/page default, ≤48); AI matches render from `POST /api/ai/car-finder` (real listings only).
- **Save heart**: optimistic toggle for signed-in users; signed-out → toast + redirect to sign-in.

## 6.5 Vehicle detail (`#/vehicle-detail/<id>`)

- **Sees**: gallery + thumbnails, price/mileage/specs (10-row grid incl. ref code and real view count), description, seller card (dealer org with phone/verified badge + storefront link, or private seller with "verified seller" only if KYC-approved), similar listings (±40% price, same body/make), safety alert ("stay safe when buying"), action card.
- **Can do**: Enquire (dialog, phone-share toggle), Save, Share, Report (6 reasons incl. scam/stolen/duplicate → `POST /api/reports`), Book test drive and "Ask about this vehicle" (org listings only), open the storefront.
- **Behind the scenes**: `GET /api/vehicles/[id]` (non-published → 404 unless owner/org/staff; `reviewNote` only for privileged viewers); a fire-and-forget `POST /api/vehicles/[id]/view` increments views with 24h per-IP dedupe (`ViewEvent` SHA-256 IP hash, unique key, race-safe) and counts campaign clicks.

## 6.6 Vehicle comparison / saved vehicles / saved searches

Compare is client-side over fetched cards (max 3, fixed compare bar). Saved vehicles/searches are server rows (Part 6.3). No alert emails exist for saved searches.

## 6.7 Enquiries & messaging

Enquiries are per-listing Q&A threads (statuses OPEN/ANSWERED/CLOSED). Conversations are the general-purpose inbox (`POST /api/conversations` with subject/kind/vehicle/service reference; thread reuse per (customer, org, vehicle); attachments ≤5 must be `/api/media/` URLs; close/reopen/archive both sides; unread flags per side; 30/5min send rate limit). Attachments rely on the **missing upload endpoint** (Part 20 gap).

## 6.8 Showroom storefronts (`#/showrooms`, `#/showrooms/<orgId>`)

Directory of ACTIVE dealer orgs with real listing counts and 3 vehicle thumbnails each → storefront page (detailed in Part 14): hero, verified badge, hours/open-now, inventory with per-vehicle "Ask"/"Book test drive", reviews (earned-only), FAQ, contact options (call/WhatsApp marked "leaves CARMAZE"), stats strip.

## 6.9 Garage storefronts & service bookings (`#/garages`, `#/garages/<orgId>`)

Directory with category chips (12 service categories), county filter, text search, ratings; GarageAssistant AI (symptoms → suggested categories); Request-a-quote dialog → `POST /api/service-requests`. Storefronts add services & pricing cards, "Book this service" (priced services), **Hand over vehicle** (digital custody handover dialog — Part 9/10), reviews, hours.

## 6.10 Quote requests → bookings

Customer journey: request → garages quote (customer sees quotes in Account → Requests) → Accept → Booking CONFIRMED → garage schedules → starts → completes (+250 loyalty points, review prompt). Every transition is guarded server-side; customers can cancel bookings too.

## 6.11 Test drives

Only on org (dealership) listings; requires licence confirmation checkbox; window 1h–60 days ahead; lifecycle REQUESTED → CONFIRMED → IN_PROGRESS (odometer-out, fuel-out, condition-out, releasedBy recorded) → COMPLETED (odometer-in, fuel-in, returnedBy) / NO_SHOW / CANCELLED; customer cancels from Account → testdrives. A completed drive is what "earns" the ability to review that dealership.

## 6.12 Vehicle Protection (customer side) — see also Part 10

Account/My Garage → protection tab: custody cards with an 8-step status stepper; handover facts (authorised spend cap, declared condition/valuables, road-test permission); road-test authorise/decline; "I'll collect personally" or "Authorise someone else" (name + Kenyan phone → single-use 6-digit code shown once, 48h validity, revoke anytime); dispute (creates incident + freezes custody); report incidents (12 categories incl. STOLEN_VEHICLE, with evidence upload and an explicit "contact the police; CARMAZE is not an emergency service" note); incident notes and status tracking.

## 6.13 Notifications

Bell (mark-all-read on open) + tab; every notification carries a deep link; types include LISTING_PUBLISHED, QUOTE_RECEIVED, BOOKING_*, CUSTODY_UPDATE, PAYMENT_CONFIRMED, INVOICE_ISSUED, DOCUMENT_*, ACCOUNT_SUSPENDED, TRUST_INVITE, CREDIT_*, BROADCAST, STAFF_*, MEMBERSHIP_*, LOYALTY_POINTS, SUPPORT_TICKET_UPDATED, LOGISTICS_*.

## 6.14 Reviews

Only "earned" reviews: a customer can review a garage after a **COMPLETED booking** or a dealership after a **COMPLETED test drive** (server-verified, not self-declared). One review per org per author (updatable); first publication earns +100 points; authors display as first names only. No profanity filter — moderation is via reports.

## 6.15 Support & disputes

`#/info?view=faq` contact form → `POST /api/support` (works signed-out; signed-in identities are bound server-side) → `SupportTicket` → staff handle in Admin → Support (in-progress/resolve with recorded response; submitter notified). Custody disputes and incidents are separate, richer systems (Part 10).

## 6.16 Account settings & privacy

Profile (name/email immutable; phone editable), verification, MFA, theme (light/dark), privacy card; suspension means losing everything instantly (Part 5.18).

# PART 11 — VEHICLE PASSPORT AND MY GARAGE (`#/my-garage`)

My Garage is the customer's private vehicle vault (auth-gated; sign-in card when logged out). Two top tabs: **garage** and **protection** (protection = §6.12).

## 11.1 Adding a vehicle

Dialog: make*, model*, year, plate (uppercased), colour, mileage, purchase date, purchase price, notes → `POST /api/mygarage/vehicles` → `MyVehicle` row (owner-scoped forever). Deleting a vehicle cascades its records and reminders (confirm dialog).

## 11.2 Vehicle verification & provenance distinctions

There is **no government/NTSA verification integration** — CARMAZE never claims one. What exists, and how the platform distinguishes provenance:

| Source | Where it shows | Trust marker |
|---|---|---|
| **Customer-entered** | My Garage vehicles, records, reminders | Plain data; explicitly user-owned; deletable by the owner |
| **Business-submitted** | Garage custody completion data (work done, final odometer, cost, photos), garage service records referenced by `garageOrgId` | Attributed to the org via the custody pipeline; immutable event timeline |
| **Independently inspected** | Nothing yet — inspection partners exist in the Partner directory but no inspection-record model is wired to My Garage | — |
| **Externally verified** | Nothing — no external registries are integrated | — |
| **Platform-verified** | Seller KYC (`SELLER_VERIFIED`), business verification (org `verified`), document verification | Only staff decisions; every staff view of a document is access-logged |

## 11.3 Vehicle history / service & repair records

Inner tabs on the selected vehicle:
- **records** — timeline of SERVICE / REPAIR / INSPECTION / MODIFICATION / OTHER entries with date, description, cost, mileage, optional garage reference; `POST/DELETE /api/mygarage/records`. Logging a higher odometer **syncs the vehicle's mileage**.
- **reminders** — SERVICE / INSURANCE / INSPECTION / LICENSE / CUSTOM with due dates; Done/Dismiss/Reactivate; **true recurrence**: marking DONE with an interval rolls the next occurrence forward (past-due dates roll too, guarded ≤100 iterations) with a toast explaining the reschedule.
- **details** — mileage updater, purchase info, notes.

## 11.4 Mileage, modifications, warranties, documents

Mileage is a field + record-sync (Part 11.3). Modifications are a record type (and the Customizer path can create a MODIFICATIONS service request). Warranties: only on purchased parts (Product `warrantyMonths` → WarrantyClaim workflow); there is no vehicle-warranty model. Receipts/documents: `ServiceRecord.receiptUrl` exists in the schema but **no upload endpoint** exists to fill it (gap).

## 11.5 Maintenance reminders & notifications

Reminders are in-app records with due badges (Overdue / Due soon). The UI says honestly: **no SMS/email reminders are sent in this deployment**. There is no scheduler; visibility comes from the dashboard.

## 11.6 Ownership changes & sharing

No ownership-transfer flow exists (a re-sold car's history stays with the original account; a new owner starts a fresh My Garage). Sharing: nothing shareable from My Garage today; the closest analogue is the 3D Customizer's share links and the custody record's shared timeline between the customer and the garage.

## 11.7 Privacy and access control

Every `/api/mygarage/*` query resolves `myVehicle.userId = session user.id`; foreign vehicle IDs 404-masquerade; deletes cascade records/reminders. Custody links (`myVehicleId`) are validated to belong to the handover customer at creation.
